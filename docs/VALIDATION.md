# 单仓库离线部署验证

验证日期：2026-11-04。环境：Linux x86_64，普通用户，Bash。仓库内核为通用 amd64-v1 构建，版本 v1.19.27；已检查构建元数据为 `GOAMD64=v1`。

## 已通过的验证

- 按 Git 忽略规则生成临时仓库并实际克隆；克隆包含内核、yq、subconverter、Country.mmdb、geosite.dat 和完整面板，不包含任何个人订阅、`private/` 或 `.env.install.local`。
- 在隔离用户目录、进程和网络的环境中运行默认安装。安装时用拒绝联网的 curl/wget 包装命令检查调用，未出现调用；外部网络也不可达。
- 安装前对六个程序包/数据资源完成 SHA-256 校验；损坏、缺失和 CPU 不兼容的情况有独立 smoke 检查。
- 首次自动创建 shell 配置，加载后通过本地 HTTP 测试服务器执行 `clashctl sub add --use URL`。
- 测试订阅包含 `GEOIP,CN`、`GEOSITE,cn`，并故意设置 `geodata-mode: true`、自动数据库更新和远程面板 URL。校验与最终运行都使用本地策略覆盖这些设置，原订阅仍被保留。
- Country.mmdb 与 geosite.dat 在运行前后保持与仓库文件一致，未创建 GeoIP.dat。代理请求通过 mihomo 端口到达测试 HTTP 服务并取得预期响应。
- 独立本地资产 smoke 检查在断网环境中使用真实内核和 yq；strace 中 IPv4/IPv6 connect/send 尝试为 0。
- 资产缺失会在验证/启动时明确报错；管理命令不再查询公网 IP 或调用内核在线升级接口。
- 在同一次断网部署中继续添加非原生订阅，随包 subconverter 使用本地模板和规则成功转换；第二次订阅写入立即完成。已修复后台内核继承订阅锁及转换器清理时误报失败的问题。
- 完整流程最终通过：克隆 → 断网安装 → HTTP 订阅 → 本地 GEOIP/GEOSITE → 代理请求 → 第二个订阅转换 → 卸载。
- 命令入口、安装、导入和资产 smoke 检查，以及全部 shell 语法检查通过。

测试没有改变原机器的代理安装或真实 shell 配置。

## 范围

部署不再访问外部程序、面板或数据库下载地址。订阅 URL、节点连接和订阅自己声明的远程 providers 仍属于正常联网使用；测试使用本地测试订阅，没有验证任何个人提供商的远端节点。当前包不含 ASN.mmdb，遇到依赖该数据库的规则会报本地缺失，不会自动下载。

基础 Linux 工具需由目标系统提供，详情见 README。普通用户流程已实测，root/systemd/TUN 未在本轮实际部署。
